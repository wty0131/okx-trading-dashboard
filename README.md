# 🪙 OKX Trading Dashboard

一个**跑在你自己电脑上**的加密货币量化研究面板：看行情、测策略、跑历史回测、开"模拟盘"验证想法——**全程不花一分钱、不碰你的真实资金**。

- 📈 真实行情（BTC/ETH/SOL/BNB/DOGE… 10 个主流币）
- 🧪 7 个开箱即用的交易策略，参数随便调
- 📊 历史回测：收益、回撤、夏普、胜率一目了然，可导出 CSV
- 🧾 **模拟盘**：用真实行情在本地模拟撮合（手续费+滑点假设），看你的策略"如果实盘会怎样"
- 🔒 想接真实账户？只读查询都行，密钥只保存在你自己的电脑上

> ⚠️ 本项目仅供**学习与研究**：模拟盘与回测结果 ≠ 实盘表现，不构成任何投资建议。

## 🚀 30 秒上手

需要：**Python 3.10+**（Windows / macOS / Linux 均可）。

```bash
# 1. 下载本项目
git clone https://github.com/wty0131/okx-trading-dashboard.git
cd okx-trading-dashboard

# 2. 创建独立环境并安装依赖
python -m venv .venv
.venv\Scripts\activate        # Windows
# 或 macOS / Linux:
# source .venv/bin/activate

pip install -r requirements.txt

# 3. 启动面板
.venv\Scripts\python -m streamlit run app\Home.py
```

浏览器会自动/手动打开 **http://localhost:8501** 即可使用。

> 💡 **Windows 用户更省事**：装完依赖后，以后直接双击项目里的 `OKX交易系统.bat` 就能启动。

**无需任何 API Key** 就能看行情、回测、开模拟盘——继续往下看怎么玩。

## 🧭 界面长什么样、怎么玩

侧栏页名为中文：**总览 / 行情 / 策略库 / 回测 / 模拟盘 / 设置 / 实盘交易**。

| 页面 | 你能做什么 | 建议第一次这样试 |
|---|---|---|
| 📊 **总览** | 所有模拟盘账户的权益汇总、净值曲线 | 先看一眼，稍后开了模拟盘再回来 |
| 📈 **行情** | 实时价 + K 线蜡烛图（带均线、成交量） | 选 `BTC-USDT` → 点「刷新行情」 |
| 📚 **策略库** | 查看 7 个内置策略和它们的参数 | 随便展开看看，理解"策略=规则" |
| 🧪 **回测** | 用历史数据测试一个策略的表现 | 交易对 `BTC-USDT` → 策略 `macd_trend` → 点「▶️ 运行回测」 |
| 🧾 **模拟盘** | 让策略"从今天起"在**模拟资金**上跑（本地记账，不碰真钱） | 选 `sma_cross` → 初始资金 10,000 → 「🚀 启动」 |
| ⚙️ **设置** | 行情源状态、（可选）填你的 API Key | 看看数据链路是否正常即可 |
| ⚡ **实盘交易** | **仅当启动时设 `OKX_TRADING_ENABLED=1` 才可用**；开启后真实下单/撤单（含单笔/单日上限与 `CONFIRM` 确认） | 未开启开关时本页只显示说明与只读账户数据 |

**玩法建议**：先在「回测」页用历史数据筛出顺眼的策略 → 再到「模拟盘」启动它 → 之后每天点一次「更新」（或对某账户点「更新一次」），观察它在真实行情下模拟账户的浮盈浮亏——**这就是不花真钱的"实盘预演"**。

### 内置的 7 个策略
SMA 双均线 · EMA+RSI 趋势过滤 · 布林带均值回归 · MACD 趋势 · 唐奇安通道突破 · RSI(2) 超跌反弹 · 动量跟随

每个策略的参数都可在页面里调整（滑块/数字框），`strategies/` 下新增一个 `.py` 文件即可注册你自己的策略。

## 🔑 想连自己的 OKX 账户？（可选，只读优先）

默认**完全不需要**。如果你想把真实账户余额/持仓也展示出来：

1. 去 OKX → **API 管理** → 新建 Key，权限只勾 **「读取」**（先别勾交易）；
2. 在该 Key 的 **IP 白名单**里加入你当前网络的出口 IP（如果你走代理，就加代理的出口 IP）；
3. 回到面板 **「设置」页**：粘贴 API Key / Secret / Passphrase → 「保存并测试」；
4. 面板只会在你的电脑上保存这些信息（写进项目根 `.env`，已被 git 忽略），**不会上传、不会出现在日志里，界面也只显示末 4 位**。

> 🔐 记住三点：`Passphrase` 是建 Key 时单独设置的 API 密码（不是登录密码）；任何真实交易请再三谨慎；本面板默认只做只读与 dry-run 校验，不下单。

### ⚡ 关于「实盘交易」页（只有想真实下单才需要看）
「模拟盘」与「实盘交易」是**两个完全独立的页面**：前者本地记账、永不碰真钱；后者是真实下单入口，**默认关闭**——未设置 `OKX_TRADING_ENABLED=1` 时该页只显示说明与只读数据，**不会出现下单表单**。

要真正下单，必须**同时**满足：

1. **打开实盘总开关**（二选一）：
   - 面板里 **「设置」页 → ⚡ 实盘交易总开关 → 勾选确认 → 开启**（写入本机 `.env`，即时生效、重启保留）；或
   - 启动时设环境变量：`$env:OKX_TRADING_ENABLED="1"`（PowerShell）后再启动面板；
2. 你的 API Key **勾选了「交易」权限**，且请求出口 IP 在该 Key 的白名单内；
3. 页面里勾选风险确认 → 输入 `CONFIRM`；
4. 下单金额受**单笔上限 / 单日累计上限**约束（默认 10 / 30 USDT，可在页面调整）。
   这是 **fail-closed** 闸门：**无法估算订单 USDT 金额时（行情不可用、参数异常等）一律拦截**，而不是跳过上限检查；单日累计金额**落盘**保存（`data/trade_usage.json`，UTC 日期分桶），刷新页面**不会**清零。

> 💡 强烈建议：策略先在「模拟盘」跑够时间再考虑小额手动实盘；本面板**不提供策略自动下单**。

## ❓ 常见问题

**行情加载不出来 / 很慢？**
行情源按 **OKX → Binance → CoinGecko** 自动降级，并有本地缓存（`data/cache/`）。如果你的网络访问不了境外交易所，可配置代理后再启动：
```
# 在系统环境变量或 .env 中设置
OKX_PROXY=http://127.0.0.1:7897
```
数据成功拉取后会自动缓存，第二次会快很多。

**模拟盘和实盘有什么区别？**
模拟盘 = 真实行情 + **本地模拟撮合**（默认计入 0.1% 手续费 + 0.05% 滑点），只在你电脑上记账，不会向 OKX 发送任何交易指令。回测同理，只是改用历史数据一次性跑完。

**结果存在哪？**
模拟盘状态在 `data/paper_state/`（1D 与 1H 各一套账户），回测结果可一键下载 CSV。这些运行数据都已被 git 忽略，不会提交到仓库。

**怎么让模拟盘"每天/每小时更新"？**
页面里点「更新一次」即可手动推进；想批量推进全部账户，可在项目目录跑：
```bash
.venv\Scripts\python scripts\run_paper_update.py
```

**会不会误碰我的真实资金？**
不会。不填写 API Key 时面板与 OKX 只发生**公开行情**请求；账户接口默认 `dry_run`（只构造签名、不发送）。本项目不含任何自动下单逻辑。

**我的密钥安全吗？**
密钥只存本机 `.env`（`.gitignore` 已排除）。请勿把 `.env`、API Key 截图或你的 IP 白名单信息分享给任何人。本仓库本身不含任何真实密钥或个人账号信息。

## ✅ 正确性与安全修复记录

### 2026-09-11

**① 未收盘的「半根 K 线」被当成收盘价（数据正确性）**

OKX 的 candles 接口会连同**正在形成的当前 K 线**一起返回（其 `confirm` 字段为 `"0"`）。
原实现在列裁剪时把 `confirm` 丢弃，调用方无从判断，模拟盘据此记账会污染净值；
**更严重的是它会把锚点推进到该 bar，导致这根 K 线的最终数据此后被永久跳过**
（增量只补 `索引 > 锚点` 的部分）。

修复：
- `OkxClient.get_candles(..., drop_unclosed=False)` 新增参数，可直接丢弃未收盘的最后一根；
- `data/market.is_bar_closed(ts, bar)` / `drop_unclosed_bars(df, bar)` —— 按**时间**推算
  （`ts + 周期 ≤ now`），等价于 `confirm` 语义但**可作用于本地缓存**（缓存只有 5 列 OHLCV，没有 confirm）；
- 模拟盘更新路径（`app/pages/4_Paper.py`）只喂已收盘的 K 线。

**② 实盘下单限额可被静默绕过（资金安全）**

原上限判定写作 `est_usdt is not None and est_usdt > cap_single`。一旦行情不可用或估算异常，
`est_usdt` 为 `None`，**两道金额上限被整体跳过**，一笔无上限的真实订单会被放行。
另外当日累计金额只存 `st.session_state`，**页面一刷新即归零**，「单日累计上限」实际退化为
「单次页面会话上限」。

修复：判定逻辑抽到 `app/trade_limits.py`（可独立测试），改为 **fail-closed** 并落盘累计。

**③ 保存 API Key 会抹掉 `.env` 里的其他配置**

设置页原实现**整文件覆写** `.env` 为 3 行，会抹掉 `OKX_PROXY` / `OKX_HTTP_PROXY` /
`OKX_HTTPS_PROXY` / `OKX_MARKET_OFFLINE` / **`OKX_TRADING_ENABLED`**。
最坏的连锁反应是：用户只是想改个代理，**实盘总开关却被静默关闭（或打开）**。

修复：新增 `app/env_file.update_env_file()`，**按 key 增量更新**——只替换目标键，
其余行（注释、空行、其他键与原有顺序）逐行保留；写盘前备份为 `.env.bak`，
写盘用「临时文件 + 原子替换」，中途崩溃不会留下半截文件。

**④ 新增两个可测试的纯逻辑模块**

`app/pages/6_Trade.py`、`app/pages/5_Settings.py` 是 Streamlit 页面，**import 即渲染**，
无法在自检中导入测试。因此把资金安全相关的判定抽到：
- `app/trade_limits.py` —— 限额闸门 + 当日累计持久化
- `app/env_file.py` —— `.env` 增量更新 + 密钥脱敏

这两个模块**绝不打印、不记录、不返回任何密钥值**，只回报被更新的键名。

## 📁 项目结构（简单版）
```
app/            界面（Streamlit，中文导航：总览/行情/策略库/回测/模拟盘/设置/实盘交易）
  trade_limits.py   实盘限额闸门（fail-closed）+ 当日累计持久化
  env_file.py       .env 按 key 增量更新 + 密钥脱敏
okx/            OKX API 客户端（纯 requests，无第三方交易所库）
strategies/     策略库（自动注册，可加自己的策略）
backtest/       历史回测引擎
paper/          本地模拟盘引擎（1D 日线 / 1H 小时线）
data/           行情缓存与模拟盘状态（不入 git）
scripts/        自检与批量推进脚本
```
